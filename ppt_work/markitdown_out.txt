# FUSION PRIVACY AGENT

![](Picture10.jpg)
Your Team Name
Proposed Solution

An on-device vision pipeline (BlazeFace, YOLOv8n, Florence-2, Tesseract OCR, NER) detects faces, passwords, card numbers, emails and phone numbers directly inside the browser.
Only a redacted screenshot and a structural DOM manifest ever leave the device -- a server-side LLM plans every click, type or scroll from that sanitized context alone.
A confirmation gate pauses before any high-risk action, and a floating pill plus a full chat side panel let a person drive the whole flow by typing or by voice.

# TECHNICAL APPROACH

Chrome Extension (MV3, TypeScript)

![cpu.png](Picture17414.jpg)
Client: a Manifest V3 Chrome extension in TypeScript -- ONNX Runtime Web, Transformers.js and MediaPipe run fully on-device, inside a chrome.offscreen document immune to a host page's Trusted Types policy.
Server: a Python FastAPI service exposing one swappable get_next_action() -- works with any OpenAI-compatible LLM (OpenAI, Groq, OpenRouter, or a local model).

# FEASIBILITY AND VIABILITY

![](Picture10.jpg)
Your Team Name

Model hallucinated CSS selectors -> fixed by handing it real DOM element selectors, not a screenshot alone

![check.png](Picture17411.jpg)
Runs on hardware already in every user's pocket -- Chrome's WebGPU/WASM support plus ~420MB of quantized on-device models, no server-side GPU needed for perception.
Real challenges hit while building: hallucinated selectors, browsers silently blocking workers, and unvalidated navigation targets.
Solved with structural fixes, not patches -- see the three cases on the right.
